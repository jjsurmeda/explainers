LayaVSJev

Typed answers in ~33–40 ms. No prose to parse. No invented labels.

Laya reads a piece of text, answers the typed questions you give it, and returns a probability for every option in a single forward pass. You calibrate them on your own data. It is an Apache-2.0, run-it-yourself alternative to TypeSafe's Jev, and it speaks the same /v1/systemone API.

Hi! Let me walk you through Laya, the open decision model that answers in tens of milliseconds.
What it is

A decision model, not a chatbot

A generative LLM writes its answer one token at a time, and the answer may not match your labels. Laya never writes. It scores every allowed answer at once. TypeSafe calls this class of model "System 1": fast, reflexive judgments.

Generative LLM

Writes, then you parse

> Which department should handle this?
This looks like it's mostly a billing concern, though it could also involve account management…
Output: free textOff-list: possibleConfidence: none
Laya · one forward pass

Scores every option at once

> department ∈ {billing, technical, other}
billing0.94
technical0.04
other0.02
Output: typed JSONOff-list: impossible (always one of your options)Confidence: probabilities, calibrated on your data

How it works

One pass, five stages

A bidirectional encoder (ModernBERT-large for English, mmBERT-base for other languages) with a small decision head. Each candidate answer gets its own [MASK] slot, so the model reads the text and all options together.

[CLS] Hi, we were billed twice for March… [SEP] Which department should handle this? [SEP] [MASK] billing [MASK] technical [MASK] other [SEP]

Trained with RLCD (Reinforcement Learning for Calibrated Decisions): proper scoring rules (log + spherical score, plus ranked probability score on ordinal questions) reward probabilities that match reality. Schemas are set per request, so new labels need no retraining.

What problem it solves

Using an LLM to pick a label is overkill

Many production workflows are full of small decisions: route this ticket, flag this message, gate this agent action. A generative model costs time and money, and you still parse prose.

Latency

Too slow for the request path

Hundreds of ms per call rules out inline gating. Laya: 32.8–39.5 ms on a T4.

Reliability

Answers outside your list

Free text invents labels and breaks parsers. Laya only returns options you defined.

Trust

No usable confidence

Scores calibrated on your data support rules like "act above 0.8, escalate below".

Cost

Metering adds up

Self-hosted: no per-token fee (you still pay for GPUs). Laya Studio lists $0.0294 / 1M input tokens, about 30% under Jev.

Sovereignty

Data can't leave

Open weights run air-gapped. Laya Studio says it keeps no content and runs on Swiss GPUs.

Language

Non-English inboxes

Auto-routes to a multilingual checkpoint for 100+ languages.

Question types

Three ways to ask

Every request is a piece of text (the "state") plus a set of named, typed questions. You can ask several at once.

choice

Pick one option from a fixed set. Returns a probability for every option.

Which department?

score

Rate on ordered levels you define. Returns the expected position on the scale.

How urgent, 1 to 3?

noul

Probability that a yes/no statement is true.

Threatens to leave?

Decision guide

        
Different strengths, compatible interfaces

        

          
Choose Laya when
    
            
  • A handful of options (under ~20)
  • It's in the request path and must answer in tens of ms
  • Data must stay on your infrastructure
  • You can fine-tune and calibrate
  • Very high volume, no per-token bill

          
Choose Jev when
    
            
  • You need good answers on day one
  • Wide option sets (dozens to 255)
  • Long inputs, up to 32K tokens
  • You'd rather pay per call than run GPUs
  • You already route through OpenRouter

        

        

          
Incoming text→Laya · ~35 ms→ confident →Act· unsure →Jev · 32K ctx→Act / human

          
Laya's server uses Jev's /v1/systemone request and response shape, so adding a fallback takes little code.

        

        
Sources: Laya Studio [2] · OpenRouter [5] · TypeSafe docs [6]

      

      
Laya fits narrow, fast decisions you can fine-tune for. Jev fits when you need strong answers on day one or wide option sets. They can share one pipeline.

    


    
    

      

        
Know before you ship

        
Limitations

        

          
Weak zero-shot
Base models score 0.342–0.362 on typed-decisions, below a 0.461 majority baseline.

          
Wide label sets
Accuracy drops past ~20 options (0.425 on Banking77).

          
Short context (EN)
The English model leaves ~320 tokens for your text. Multilingual defaults to 1K, up to 8K.

          
Ordinal scores
score is weakest (0.372 on SST-5).

          
Over-confident
ECE is 0.466 before temperature fitting. Unsupported scripts can be wrong while very sure (Khmer: 0.000 accuracy at 0.952 confidence).

          
noul quirks
Can follow option labels instead of the text. Fallback: a two-option choice with neutral keys.

          
Act/escalate head
Not usable yet. Gate on confidence.
